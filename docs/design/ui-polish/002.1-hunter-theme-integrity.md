# 002.1 — Hunter Theme Integrity

**Area:** Hunter → Create Campaign (all five steps) and Mission Setup
**Type:** Pre-existing theme defect, found during #002 founder review. Not a #002 regression.
**Files:** `src/pages/Hunter/CreateCampaign.jsx`, `src/components/hunter/MissionSetup.css`

## The defect

Create Campaign hardcoded a light page (`bg-white`, `bg-gray-50`, `text-gray-900`)
regardless of theme. In the four dark themes (Mission, Navy, Dark Side, The Force) the
workspace stayed white. Mission Setup was worse: its own CSS used theme foregrounds
(`--text-primary`) on a hardcoded `background: white`, so in dark themes the contact
preview was near-white text on white, on `main`, before #002.

The #002 heading regression (a global heading `color`) made the page headings
unreadable too. That was fixed inside #002 (`c0b83e6f`); this entry fixes what was
already wrong underneath.

## The change

Colours only, as existing theme tokens. No markup, logic, state or typography changes;
every edited line in `CreateCampaign.jsx` is a `className` string.

| Was | Now |
|---|---|
| page `bg-white text-gray-900` | `--bg-primary` / `--text-primary` |
| sticky step bar `bg-gray-50` | `--bg-nav` |
| step cards `bg-gray-50 border-gray-200` | `--bg-card` / `--border` |
| inputs `bg-white border-gray-200`, purple focus | `--input-bg` / `--input-border` / `--input-focus` |
| contact rows (unselected / selected) | `--bg-card-2` / `--accent-bg` + `--accent` border |
| step pills (inactive / active) | `--bg-secondary` + `--text-secondary` / `--accent-bg` + `--accent-border` + `--text-primary` |
| Back buttons `bg-gray-200` | `--bg-secondary`, `--border-2` outline, `--text-primary` |
| disabled buttons `bg-gray-200 text-gray-400` | `--bg-secondary` / `--text-faint` |
| greys 700 / 500 / 400 | `--text-primary` / `--text-secondary` / `--text-secondary` (labels) or `--text-faint` (chevrons, disabled) |
| purple tints and icons | `--accent-bg` / `--accent` |
| error / warning banner text | `--text-primary` on the existing translucent red/amber tint; icons `red-500` / `amber-500` |
| Mission Setup `.contact-preview` white | `--bg-card` |
| Mission Setup guidance `#92400e` / `#78350f` on amber tint | `--text-primary` on `--status-warning-bg` |

Deliberately kept: the pink→purple gradient primary buttons with white text (brand),
the blue Gmail-connect button (now with an explicit white label), translucent banner
borders, all font sizes and weights.

four dark themes (last column).

## Deliberately not changed

- **Status tokens are missing from the Dark Side, Light Side and The Force theme blocks** in
  `src/index.css`, so they inherit the light root values. Dark amber and red text then lands
  at about 2.4:1 on those near-black surfaces. This page avoids status-coloured *text* for
  that reason. Filling in the theme blocks is a global theme change, left for its own entry.
- Template Library (step 4) is already token-driven; untouched.
- Engagement intent cards were fixed in #002 (`.intent-option` → `--bg-card`).
- No typography changes (Mission Setup keeps its rem sizes).

## Verification

- Every edited `CreateCampaign.jsx` line is a `className` string; handlers, state and step
  logic are unchanged.
- Visual check of steps 1–5 in all seven themes on the deploy preview (before/after
  screenshots attached to the PR).
