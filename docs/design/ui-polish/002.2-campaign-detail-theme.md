# 002.2 — Campaign Detail Theme Integrity

**Area:** Hunter → campaign detail (`/hunter/campaign/:id`), plus the shared button and icon colours
of the campaign list (#003.2) and wizard (#002.1), so the three pages match.
**Type:** Pre-existing theme and contrast defects. Recorded in #003.2; not a regression.

## The defect

`CampaignDetail.jsx` hardcoded a light page: `bg-white`, `bg-gray-50`, grey text, and -400 status
colours (about 85 colour classes across loading, error, main view and the send dialog). In the four
dark themes the page stayed white. Several elements also failed contrast **in light themes**:

| Element (before) | Contrast |
|---|---|
| Status pill "Completed" (green-400 on green tint) | 1.5:1 |
| "Sent" count (green-400 on the light header) | 1.7:1 |
| "Loading campaign…" (cyan-400 on white) | 1.8:1 |
| Status pill "In Progress" (blue-400 on blue tint) | 2.0:1 |
| RECON pill (purple-400 on purple tint) | 2.1:1 |
| Gradient buttons, no label colour (near-black on purple-600) | 3.3:1 |

The brand gradient itself was also below the bar for a white label at its pink end:
white on pink-500 is **3.5:1**, and white on blue-500 is **3.7:1**.

## The change

Colours only. Every edited line in the three JSX files is a class string; no markup, state,
handlers, data or permissions change. Global theme tokens aren't modified.

**Detail page:** the same token mapping as #002.1.
- Page → `--bg-primary`; sticky header → `--bg-nav`; message cards, error card and dialog panel →
  `--bg-card`; subject and body previews → `--bg-card-2`; inputs → `--input-*`.
- Primary text → `--text-primary`; labels and metadata → `--text-secondary`.
- Status pills match the campaign list badges: Draft → `--bg-secondary` + `--text-secondary`;
  In Progress → `--accent-bg`/`--accent-border` + `--text-primary`; Completed →
  `--status-success-bg` + green border + `--text-primary`.
- "Sent" count, "✓ Sent …", RECON pill and error text → `--text-primary` (hue stays in tints and icons).
- Secondary buttons → #002.1's Back style (`--bg-secondary`, `--border-2`, `--text-primary`).

**All three pages: brand buttons, one step darker, with explicit white labels.**

| Stop | Before | After | White label |
|---|---|---|---|
| Gradient start | pink-500 (3.5) | **pink-600** | 4.6:1 |
| Gradient end | purple-600 | purple-600 | 5.4:1 |
| Hover start / end | pink-600 / purple-700 | **pink-700 / purple-700** | 6.0 / 7.0:1 |
| Blue button | blue-500 (3.7) | **blue-600**, hover blue-700 | 5.2 / 6.7:1 |

The list's New Campaign button used `opacity: 0.9` on hover, which lowers label contrast. It now
darkens to the hover gradient instead.

**Meaningful icons: theme-adaptive hue.** No fixed Tailwind shade clears 3:1 on both the light and
the dark surfaces. green-600 is 2.8:1 in Light Side; green-700 drops to 2.4:1 in Navy. The fix is
`color-mix(in srgb, <hue> 70%, var(--text-primary))`, built from existing tokens: it darkens in light
themes and lightens in dark ones, keeping the hue. Browsers without `color-mix()` drop the declaration
and the icon inherits the text colour, which is still readable.

| Icon | Hue | Minimum across 7 themes |
|---|---|---|
| Sent check (detail) | green-600 | 4.4:1 |
| Gmail-limits warning (wizard) | amber-600 | 4.7:1 |
| Error alerts (detail, wizard) | red-500 | 4.9:1 |
| Mail / Sparkles (accent) | `--accent` | 3.3:1 |

## Regression guard

`src/test/hunterCampaignThemeGuard.test.js` parses every class string in `CreateCampaign.jsx` and
`CampaignDetail.jsx` and fails on any literal palette colour outside an allowlist: the checked brand
stops, blue-600/700, `text-white`, the dialog backdrop, and translucent status tints. `text-white`
is allowed only in a class list that also carries a brand background, and the old pink-500 and
blue-500 stops are rejected outright. Checked against a mutated copy: it flags the reintroduced
`bg-white`, `text-gray-500`, `bg-gray-200` and a white label on grey.

## QA fix — scrolling in the campaign wizard and detail page

Founder QA on #831: Create Campaign → step 2 (Mission Setup) ran below the fold and couldn't be scrolled.

**Root cause (pre-existing, not from #002.1/#002.2):** every module route renders into a fixed-height
shell. `MainLayout` adds `.shell-fixed-height`, which sets `.main-content { height: 100vh }`, and the
content area `.page-content-full` is `overflow: hidden`. A page there has to scroll itself, as Hunter's
sections do with `flex: 1; overflow: auto`. The wizard's and detail page's roots were `min-h-screen`
with no overflow, so anything past the viewport was clipped: Mission Setup's Next, long contact
lists, long message reviews.

**Fix, local to the two pages:** the five page roots (wizard: Gmail-error and main; detail: loading,
error and main) change `min-h-screen` → `flex-1 min-h-0 overflow-y-auto`. Each page is now its own
scroll container. The existing `sticky top-0` header, with the title and step progress pills, stays
pinned while the step scrolls under it. No shell or global CSS change.

**Verified in Chrome** against the compiled app CSS, using a harness of the shell structure
(fixed-height shell, full-bleed content, page root, sticky header, tall step, actions):

| Viewport | Before | After |
|---|---|---|
| Desktop 1440×900 | no scroll container; Next unreachable | root scrolls; Next reachable; header visible |
| Laptop 1280×720 | no scroll container; Next unreachable | root scrolls; Next reachable; header visible |
| Mobile 390×844 | no scroll container; Next unreachable | root scrolls; Next reachable; header visible; content ends 56px above the bottom, clearing the shell's bottom bar |

The guard test (`hunterCampaignThemeGuard.test.js`) also asserts that neither page uses `min-h-screen`
and that every page root is `flex-1 min-h-0 overflow-y-auto`.

**Likely the same issue elsewhere, not changed here:** `CreateMission` (`.create-mission`) and
`MissionDetail` (`.mission-detail`) render into the same shell with no scroll container of their own.
They're candidates for a follow-up.

## Deliberately not changed

- Font sizes and weights (no typography work).
- The dialog backdrop (`bg-black/50`) works in every theme.
- `OutcomeTracker`, rendered inside sent messages, is its own component, so it's untouched here.
- The missing `--status-*` tokens in Dark Side, Light Side and The Force (see #002.1) are still a
  global gap. This page avoids status-coloured text, so it's unaffected.
