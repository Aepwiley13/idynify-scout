# #003.6 Unified Navigation — coordination note for the Contact Hub team

**From:** Desktop UI Polish. **Status:** design direction approved by the founder; implementation
waits for Contact Hub to integrate. Desktop Polish will not touch Contact Hub's branches or worktrees.

## What was decided

Contact Hub's expandable sidebar is now the **global navigation standard**. Every module's
sections will open under its sidebar entry, as Contact Hub's do, and the 190px section panel goes
away on desktop. See `003.6-unified-navigation.md` and the "Unified Navigation" visual proposal.

## What Desktop Polish needs from Contact Hub's architecture

Nothing new needs building on your side. We'll **generalize your mechanism, not duplicate it**:

1. **`components/layout/sidebarSlots.js` stays as is.** It's already keyed by id (`setSidebarSlot(id, el)` /
   `useSidebarSlot(id)`). 003.6 only adds more ids, one per module, using each module's
   destination id.
2. **`Sidebar.jsx`'s slot element** (today: `dest.id === CONTACT_HUB_DESTINATION.id && activeModule.id
   === dest.id && !compact`) becomes "the active module's entry, in wide mode". Contact Hub keeps
   exactly the slot it has today, with the same id and the same `.sidebar-subnav` element.
3. **`HubSidebarNav` and its styles are untouched.** For other modules, the shared `ModuleSubNav` draws
   its existing items into their slot, reusing your nested-entry treatment: indent, rule, 36px rows,
   active tint. To avoid copying, we'd like the generic parts of the `.hub-sidenav-item` rules
   available as a shared class. **Question for you:** are you happy for 003.6 to move those generic
   rules into `Sidebar.css` (leaving the `hub-*` names as aliases), or would you rather own that move
   in your integration?
4. **Compact mode:** you fall back to the page's own navigation, and that stays the same for Contact
   Hub. For other modules, 003.6b adds a keyboard-accessible flyout from the compact rail. If you'd
   like Contact Hub to use the same flyout later, it can be opt-in.
