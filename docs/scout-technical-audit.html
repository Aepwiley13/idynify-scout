Scout is a large, fully-built application with eight core modules (Scout, Hunter, Sniper, Basecamp, Command Center, Reinforcements, Fallback, RECON), an AI assistant (Barry) with 67 dedicated files and 24 backend functions, and a deep feature set across every module. The vast majority of the application is production-grade code, not placeholder.

Key findings: Two pages are fully built but orphaned (TotalMarket, legacy MissionControl). The sidebar has a duplicate "People" entry in the Scout pillar. The Cadences system is single-send only with no scheduling or multi-step sequences. There are 15+ features marked "Coming Soon" across Settings, Cadences, and Scout+. One confirmed bug exists in DailyLeads where IcpReclarificationModal references an out-of-scope variable. Barry is deeply integrated but absent from all Sniper sub-sections, most Fallback sections, and several Scout pages where new users would benefit from guidance.

Q3
Is the navigation order logical for a new user trying to go from zero to first cadence sent?

Partially. The happy path for a new user would be: Set up ICP → Discover companies (Daily Discoveries) → Save companies → Find contacts (People) → Send cadence. However:

  • ICP Settings is buried 8th in the Scout pillar, after items the user can't use yet.
  • Daily Discoveries (the primary lead source) is 3rd — reasonable, but a new user wouldn't know to start there.
  • The Cadences item appears in both the Command Center pillar and the Scout pillar, which could confuse new users about where "their" cadences live.
  • The duplicate "People" entry in Scout adds noise.
  • There is no onboarding flow that guides the sidebar sequence — the user must intuit the correct order.

The sidebar is organized by module rather than by user journey. For power users this is fine; for a new user going from zero to first cadence, the implicit steps are not surfaced.

Q8
Is the Start Cadence button visible and working correctly?

Yes, it is visible and functional, but it's a two-step indirect flow, not a direct "create cadence" button. Located at AllLeads.jsx:2092-2096:

  1. Click "Start Cadence" → toggles bulk selection mode (button label changes to "Selecting (N)")
  2. Click contacts to select them (checkboxes appear on cards)
  3. A guidance banner appears: "Click contacts to select them, then use the action bar below"
  4. A floating bulk action bar appears at the bottom with "Compose Email"

Friction
The name "Start Cadence" suggests it will open a cadence builder, but it actually enters a contact-selection mode with no immediate indication that composing email is the next step. The connection between selecting contacts and creating a cadence is not obvious to a new user.

Section 3 — Daily Discoveries

Q9
What is Daily Discoveries supposed to do and what does it actually do today?

Intended: A Tinder-style swipe-triage queue for companies and people, where users review AI-curated leads, swipe right to save or left to reject, with feedback loops that train Barry to find better leads.

Actual: Fully Built — 2,683 lines of production-grade code.

  • Companies Tab: Loads pending companies from Firestore, scores them against ICP using calculateICPScore(), presents as swipeable cards. Right-swipe accepts and auto-searches for contacts via Apollo.
  • People Tab: Shows contacts from accepted companies matching target titles as swipeable person cards.
  • Batching: Every 10 swipes shows a batch-end screen with results and Barry ICP refinement suggestions.
  • Session tracking: Daily swipe limit (25), session stats, daily streaks, streak milestones.
  • Undo: Last 5 swipes with Firestore state reversion.
  • Feedback system: Post-swipe feedback form with reason chips, 1-10 fit score slider, text notes.
  • Multi-ICP support: Switch between ICP profiles, re-scoring the queue.
  • Barry integration: Side panel chat for ICP refinement, nudge cards, ICP reclarification modal.
  • Keyboard shortcuts: Arrow keys, L/J for swipe, U for undo, B for Barry.
Q10
Does it work for a brand new user with no ICP set up?

Yes. There is an explicit ICP validation gate at DailyLeads.jsx:2002-2046. When no ICP profile exists, the page renders:

  • Barry avatar
  • Heading: "Let's set up your ICP first"
  • Explanation text about needing an ICP before curating leads
  • Primary CTA: "Talk to Barry" → navigates to /onboarding/barry
  • Secondary CTA: "Set up manually instead" → navigates to /scout?tab=icp-settings
Edge Case
If a user has a legacy companyProfile/current document with empty arrays (e.g., industries: []), the gate won't catch it — the profile is truthy but useless. Scoring would produce all-zero scores. The backend daily-leads-refresh.js:170 does guard against this by requiring at least one of industries, companySizes, or locations.

Section 5 — Cadences

Q15
From a new user perspective, is the Cadences flow complete end to end? List any gaps or friction points.

The cadence system is functional but limited to single-send operations. The end-to-end flow works — a user can create, send, and track a cadence — but there are significant gaps:

Three creation paths exist:

  1. From Cadences Dashboard: Click "+ New Cadence" → opens BulkComposeModal with zero contacts (must add manually inside modal)
  2. From AllLeads: "Start Cadence" → bulk select contacts → "Compose Email" → BulkComposeModal with pre-loaded contacts
  3. From Templates: Click a template in Cadence Library → opens compose with pre-filled subject/body, zero contacts

Critical gaps:

No Multi-Step Sequences
Cadences are single-send-and-done. No step editors, no multi-day sequences, no follow-up scheduling. The "Upcoming Cadences" section confirms "Scheduled sending coming soon." This is the biggest gap for a sales tool.
No Delete or Archive
There is no way to delete or archive a cadence. The archive button shows a "Coming soon" toast. Old cadences accumulate permanently.
25-Contact Limit
Hardcoded at MAX_CONTACTS = 25 in both BulkComposeModal.jsx and AllLeads.jsx. No way to send to more contacts in a single cadence.
No Send Confirmation
Clicking "Send to N contacts" immediately begins sending with no "Are you sure?" confirmation dialog.
Stub Features
These are visible in the UI but non-functional: "View all performance" (no-op onClick), Meetings Booked KPI ("Coming soon"), Activity tracking tab, Advanced filters, Scheduled sending, Archive action, CadenceDetail row actions (View contact, Resend), Bulk actions in CadenceDetail, Owner filter, Last Run filter, Export button.
Duplicate Search Bars
The dashboard has two search inputs (page header and table header) bound to the same state — visual redundancy.
Q16
Is the empty state on the Cadences dashboard clear enough for a new user to know what to do?

It's informational but passive. When a new user visits with zero cadences:

  • KPI cards all show 0; "Meetings Booked" shows "Coming soon"
  • Performance table: "No cadences yet" in a centered cell
  • Barry Insights: Barry avatar with "As your cadences collect data, Barry will surface insights"
  • Activity section: "Activity tracking coming soon"
  • Cadence table: "No cadences yet. Create your first cadence to get started."
  • Upcoming: "Scheduled sending coming soon"
  • Cadence Library: 5 hardcoded templates (Prospecting, Partnership, Event Follow-up, Referral, Customer Check-in) — this is the only interactive element for a new user
Missing Guidance
There is no dedicated welcome/onboarding state, no guided first-cadence tutorial, and no step-by-step CTA. The "+ New Cadence" button exists but is small and in the header. The templates section is the most useful entry point but it's at the very bottom of the page. A new user may not scroll far enough to see it.

Q20
Where is Barry absent that a new user would benefit from guidance?

17+ pages and sub-sections have zero Barry integration where new users would benefit:

All 6 Sniper Sub-Sections
Pipeline, Targets, Touches, Playbooks, Outcomes, Companies — none have Barry references. Barry could provide personalized playbook suggestions, pipeline health summaries, and tactical coaching, similar to Hunter's dashboard check-in cards.
3 of 5 Reinforcements Sub-Sections
Dashboard, Record Referral, and Leaderboard have no Barry. Barry could suggest referral talking points, highlight which contacts are likely to refer, and provide motivational nudges.
2 of 3 Basecamp Sub-Sections
People and Companies sections have no Barry, despite barryCSM.js already having full health-read and signal-detection capabilities. These are prime candidates for portfolio summaries, at-risk alerts, and expansion callouts.
All 3 Fallback Sub-Sections
People, Companies, and FallbackModule have no Barry. For contacts that have gone cold, Barry could provide re-engagement strategies, new angles from RECON data, and timing recommendations.
Scout Pages
CompanySearch (0 refs — no ICP match context on results), CompanyLeads (0 refs — no prioritization), PeopleMain (0 refs), MissionAssignModal (0 refs — no strategy suggestions during assignment).
Homepage
Zero Barry presence on the public homepage. A welcome message or live demo could help prospects understand the platform's AI capabilities.
Empty States
Most empty states across the app show static text. Only Reinforcements NurtureSection uses Barry in its empty state ("Barry will alert you when someone needs attention"). All other empty states could incorporate Barry coaching to tell new users what to do next.
